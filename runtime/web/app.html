    Connection not working?
    Use an endpoint reachable from the CoRCA server. In Docker, host.docker.internal reaches a backend on your host. An administrator must allow private hostnames with CORCA_ALLOWED_SOURCE_HOSTS. Use read-only API credentials for your provider. Check query names and service labels if discovery returns no services.
    Reconnecting replaces the active source and clears sensitivity.
    
      
    
      
    Using OpenTelemetry or an agent?
    Keep your existing Datadog, Dynatrace, or New Relic instrumentation and select that provider above. For vendor-neutral instrumentation, send OpenTelemetry metrics through a Collector into Prometheus or Grafana Cloud, then connect that query backend.
    Set a distinct service.name for each application. CoRCA reads historical metric queries; it is not an OTLP ingest endpoint or a logs/traces backend.
    # Application environment (adapt the Collector address)
OTEL_SERVICE_NAME=payments
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_METRIC_EXPORT_INTERVAL=15000
    Configure the Collector’s metrics pipeline and a durable metrics backend. If Prometheus labels differ from service.name, choose the actual query label above.

    Evaluation results
    Review the evidence behind diagnosis quality and release checks.
    
      
    Results are reported by their publisher. Software tests, incident accuracy, and AI answer quality are different evidence. A passing run does not certify production readiness.
    
      
    
      
    
      
    Publish pipeline results
    Run evaluations in your CI or Jenkins pipeline, then publish a summary here. CoRCA displays the evidence; it does not run or control the pipeline.
    Use python -m runtime.quality pilot to summarize an existing confirmed-incident assessment, or python -m runtime.quality junit for software test results. Use python -m runtime.quality publish with a separate evaluation publisher token for automated delivery.
    A deployment administrator configures CORCA_EVALUATION_TOKEN_FILE or CORCA_EVALUATION_TOKEN. This token can publish summaries only. It cannot read incidents, change settings, or deliver alerts. The operations guide includes the pipeline commands.
    
      
    Prepared evaluation JSON, up to 100 KB. Include counts, test scope, and limitations. No credentials, logs, or incident identities. Published summaries are visible to the whole team and cannot be edited.
    
    
    
    
    
      
    Team & access
    Manage who can investigate and who can change this workspace.
    
      
    Enable individual access
    Create your first administrator on the deployment host. This immediately requires everyone to sign in.
    docker compose exec corca python -m runtime.access bootstrap-admin --db /var/lib/corca/corca.db --username your.name
    You will be prompted for a password of at least 15 characters. Remote access requires HTTPS. Configure a separate CORCA_API_TOKEN for Alertmanager before switching.
    Without individual access, everyone with workspace access can change settings. Actions cannot be attributed to a person.

    Enable AI answers
    Guide answers work locally today. To enable generative answers, a deployment administrator must configure an AI provider.
    This version supports OpenAI through server settings: CORCA_HELP_AI=1, CORCA_HELP_MODEL, and CORCA_HELP_API_KEY_FILE (a mounted secret), or OPENAI_API_KEY. Restart the service after configuration. Keep the key on the server.
    Questions and recent chat messages will be sent to OpenAI with the product guides and basic setup status. Logs, credentials, raw queries, and incident contents are not automatically attached. Provider-side data policies apply. Test the selected model before sharing with customers.
